## Ticket Summary

Staff need to switch grades pages between staff, student, and parent views on:

- `/learning/grades/{USER.ID}`
- `/learning/grades/{USER.ID}/{termCode}/{FOLDER.ID}`

The selected view should affect:

- which activities are visible.
- feedback visibility.
- input vs display mark behavior.
- student weighted average / overall grade / grade average.
- cohort/class results graph visibility.
- header/meta language.
- navigation to student customisation information from the summary grades page.

## Current Code Understanding

The existing grades switcher is client-side only:

- `library/Schoolbox/Learning/Grades/templates/fragments/studentViewNavSwitcher.twig`
- `library/Schoolbox/Learning/Grades/templates/fragments/assessmentGrade.twig`
- `library/Schoolbox/Learning/Grades/templates/summary.twig`
- `library/Schoolbox/Learning/Grades/templates/gradesOuter.twig`

It renders both learner and instructor marks for staff and toggles `[data-learner-mark]` / `[data-instructor-mark]` in the browser. It does not change server-side activity visibility, feedback visibility, averages, graph data, or comments.

Relevant server-side seams already exist:

- `Schoolbox\Learning\Grades\Helper::filterAssessments(User $viewer, ...)`
- `Schoolbox\Learning\Grades\Helper::buildGraph(Markbook $markbook, User $viewee, User $viewer, ...)`
- `Schoolbox\Learning\Markbook\Markbook::__construct(..., User $viewingUser)`
- `Schoolbox\Learning\Assessment\Visibility::isVisibleToUser(...)`
- `IAssessable::isFeedbackVisibleToUser(User $viewingUser)`
- `Participant::findAuthoritativeVisibleFeedback(User $viewingUser)`

## Agreed Direction

Use a server-side effective view mode instead of extending the DOM toggle.

Add a grades-specific `viewMode=staff|student|parent` query parameter and preserve it through:

- summary page links.
- subject page links.
- term selector.
- subject selector.
- filter-panel AJAX POST route.

Resolve an effective viewer:

- `staff`: current logged-in staff user.
- `student`: viewed student.
- `parent`: real loaded parent where available, otherwise a small fallback parent user with the viewed student as child for role/relationship checks.

Parent mode is the riskiest part because some existing code checks only role type while other code checks `User::isParentOf()`.

## Important APIs Found

Parent relationship hydration:

- `Schoolbox\External\User::loadParents([$student])`
- `Schoolbox\User::getParents()`
- `Schoolbox\User::isParentOf(User $child)`
- `Schoolbox\User::getChildren()`

Filter panel behavior:

- `library/Schoolbox/Filter/templates/panel.twig` posts to `panel.route` via the submit button `data-href`.
- Current history update preserves only filter selections and `returnUrl`, so the plan avoids changing the shared filter panel by appending `?viewMode=...` to the grades report route before building the panel.

Selector behavior:

- `library/Schoolbox/Learning/Grades/templates/semesterSelector.twig` generates `data-href` values directly.
- `templates/core/sub/subjectSelector.twig` generates subject `data-href` values directly.
- Both need a passed `viewModeQuerySuffix` appended.
