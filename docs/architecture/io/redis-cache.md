# Redis Cache

Schoolbox uses a Redis instance as the data store for its cacheable data.

The Redis instance the cache uses trades off persistence for performance: the
instance stores data only in memory and is thus _not_ guaranteed to persist data
for any amount of time. The instance should therefore only be used as a cache
for data which may be generated by another process.

> See [Redis Storage](redis-storage.md) for a Redis instance which makes the
> opposite tradeoff.

The cache may store the following data:
- user-generated HTML content, once sanitised
  (e.g. stripped of unwanted or dangerous tags)
- the results of queries to the [SIS database](sis-database/README.md)
- vCal calendar files, after their recurring events have been expanded into
  concrete occurrences
- process locks for CLI commands
  (thus preventing a process from running more than once for a given instance)
- route and module cache
