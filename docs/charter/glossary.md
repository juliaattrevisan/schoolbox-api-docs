## Feature and Software Names
Term | Definition
--- | --- 
Activity | (n.) In the context of the Schoolbox software - an assessment (Due Work, Task or Quiz). In the context of work the Product Team does - a type of ticket in Jira (see [issue-types.md](issue-types.md)).
Attach Zone | (n.) An area where you can drag and drop files to upload them
Aura (or mistakenly Aurora) | (n.) A collection of PHP libraries, some of which we use more recently in our codebase, like the router - http://auraphp.com/
Breadcrumbs | (n.) See https://en.wikipedia.org/wiki/Breadcrumb_(navigation)
CK, CKE, CKEditor | (n.) An inline wysiwyg editor.
Connector | (n.) Software that connects to a SIS from which it draws data.
Date Picker | (n.) A modal that allows you to specify dates from a calendar-esque view.
Empty State | (n.) The grey block that displays when a component does not contain any content.
EOTC | (n.) "Education Outside the Classroom". A module in Schoolbox. Search for eotc/README.md.
eVi | (n.) MGGS' instance name.
Feature Tour | (n.) A walk-through of a screen or feature via a series of dialogs
Filters | (n.) Often refers to the Filters panel that exists in a few places in Schoolbox. Eg. the Pending Assessments page
Fixtures, Sports Fixtures | (n.) A feature in Schoolbox used for managing teams & games.
Foundation | (n.) The CSS framework we use - https://foundation.zurb.com/
Full Calendar | (n.) A JavaScript calendar we use throughout Schoolbox - https://fullcalendar.io/
Grunt | (n.) A task runner we use for building JS and CSS - https://gruntjs.com/
Inline Grader | (n.) A page in the LMS of Schoolbox that simultaneously shows a student's submission as well as the means to grade it
Jellytot | (n.) Internal nomenclature for what the world calls a 'kebab' menu. The dropdown menu accessed by an icon that looks like 3 vertical dots. “Jellytot” comes from the Jelly Baby sweets, which someone thought resembled the icon.
Jewellery | (n.) The colored blobs indicating an assessment's review/submission status
Joyride | (n.) See **Feature Tour**
Jube | (n.) See **Jewellery**.
Kami | (n.) A third party service that allows annotations on documents via the user interface.
Mage | (n.) A progressive form that isn't as powerful as a wizard.
Modal | (n.) https://en.wikipedia.org/wiki/Modal_window
Nat Picker | (n.) The datepicker that Natalie built. See **Date Picker**.
Notifications | (n.) Often refers to the notifications system in Schoolbox, which you can see on the top right of your page.
Pantry | (n.) A collection of all the known user interface elements and example specimens. 
Pasta Care | (n.) See **Pastoral Care**.
Pastoral, Pastoral Care | (n.) The Pastoral Care module.
Plagscan | (n.) A plagiarism checker. Third party service.
Quick Mark page | (n.) Also known as the Status Page
Resource Browser | (n.) An in-Schoolbox file and folder browser for SBFS
Rubicon Atlas | (n.) A curriculum mapping software we are soon to integrate with - https://www.rubicon.com/
Selectize | (n.) A jQuery plugin we use for our autocomplete/tag selector inputs  - https://selectize.github.io/selectize.js/
Sentry | (n.) An error reporting service that costs us money for everything it encounters.
SBFS | (n.) Schoolbox File System - the virtual file system that Schoolbox uses for storing folders, as well as their homepages, files and subfolders. 
SIS | (n.) Student Information System - an external database we integrate with
SOBO | (v.) 'Submit on behalf of'. An action a teacher or admin can do in Schoolbox to submit due work on behalf of a student.
Storage | (n.) The method through which all files uploaded to Schoolbox are stored on a file system. Sometimes colloquially referred to as _Brownhole_.
Swamp | (n.) A set of classes that transform data in the LMS  
Synergetic | (n.) The most popular SIS used by our schools
TASS | (n.) Another SIS
Three Dot Menu | (n.) See **Jellytot**
Toast | (n.) An animated javascript message to tell you about the most recent action you did 
Tot | (n.) A three-dot menu; (v.) to place something into a three-dot menu. See **Jellytot**  
Uglify | (n.) A javascript minifier. 
UPS | (n.) User Provisioning System - a cron job that automatically creates/updates user accounts etc. based on data from the SIS
Vaporwave | (n.) A set of related user interface elements that toggle on and off. 
WebDAV | (n.) A HTTP extension for the creation and update of documents. Schoolbox can act as both a client (the Drives tab) and a server (upload of files into SBFS and due work submissions).

## Processes
Term | Definition
--- | --- 
AC | (n.) Acceptance Criteria (for a Jira ticket)
Backlog | (n.) The list of issues awaiting grooming
Backlog Grooming | (v.) The process of making issues in the Backlog available for addition to the current sprint
Badges | (n.) A list of all the silly things that have happened in our workplace - https://wiki.alaress.com.au/index.php/Badges
BAU | (n.) Business as Usual (see [bau.md](bau.md))
BGB | (n.) Big Green Button - refers to the "Merge" button on github
Bling | (n.) Shortened form of "dollar symbol" $. e.g. "bling test" == $test
Chaos Test | (n.) The process of testing a system's resilience by deliberately introducing breakages to its data, environment or dependencies.
Cherry Pick | (v.) A git process/command - https://git-scm.com/docs/git-cherry-pick
Copypasta | (n.) A copy/paste that duplicates code unnecessarily. (See: [DRY programming](https://en.wikipedia.org/wiki/Don%27t_repeat_yourself))
Copy pas | (n.) A copypasta missing something critical
Curation | (v.) The process of confirming, writing AC/STR, and generally cleaning up Jira tickets.
Datums | (n. pl.) Somewhat informal rendition of "data".
Design Language | (n.) See https://en.wikipedia.org/wiki/Design_language
Dev Data | (n.) a synonym of Legacy Data
Double Diamond | (n.) The agile UX process of research, insights, ideation and development.
Dr. Hodes | (n.) The user David Rhodes in the 'legacy' dataset.
Embargo | (v.) Prevention of merging PRs in preparation for a release going out.
Express Lane |(n.) A Kanban-style process/lane in Jira that is used for tasks and stories.
Feature Freeze | (n.) A prevention on the addition of new epics to an upcoming major release.
Hat | (n.) The role in the team currently being taken on by a member of the team. See [hats.md](hats.md)/
Jypad | (n.) The iPad named after Jy because it was frequently found in, or around, his desk.
Large Data | (n.) A very large dataset used when testing for scaling and capacity, specified by `data_filename: "large.tar.gz"` in vagrant.yaml
Legacy Data | (n.) The dataset used for most development work in Vagrant, specified by `data_filename: "legacy.tar.gz"` in vagrant.yaml
Park | (v.) Defer a discussion to be resumed later
Parrotting | (v.) To supervise someone executing Self Help Initiative.
Pinning a server | (v.) To ensure that a particular server does not get automatically updated to a new minor release. Usually done to a client's dev server, when they're testing a bug fix or custom work.
Po-Po | (n.) See **Product Owner**.
Product Owner (PO) | (n.) Representative of the product team to other teams and external stakeholders. See [hats.md](hats.md)
Rebase | (n.) A [Git rebase](https://git-scm.com/book/en/v2/Git-Branching-Rebasing)
Red Worm | (n.) A colloquial term for a syntax error, so named for the worm-like appearance of the underline beneath a syntax error in PHPStorm.
Refinement | (n.) A meeting in which we go through tickets in the backlog and discuss in order to come to a shared understanding of what is required, so that the tickets can be made ready for working on.
Retro | (n.) Sprint Retrospective - see [ceremonies.md](ceremonies.md)
Sales Data | (n.) The dataset used in client demos, specified by `data_filename: "sales.tar.gz"` in vagrant.yaml
Scrum Master (SM) | (n.) Administrator of the product team. See [hats.md](hats.md)
Self Help Initiative | (v.) Merging your own branch.
Spike | (v.) Any activity conducted for discovery and preparation purposes prior to commencing development, such as research and wireframing.
Sprint | (n.) A time window within which the Product Team commits to or forecasts delivery of a defined set of issues.
Standup | (n.) Short daily meeting conducted while standing - see [ceremonies.md](ceremonies.md)
Storm | (n.) PHPStorm - the IDE used across the team.
STT | (n.) Steps To Test.
STR | (n.) Steps to Reproduce (for a bug)
Strike Team | (n.) A team of 2-3 developers assigned to work on a new feature.
Tagging | (v.) The process of attaching a tag to an issue in Jira, usually with the purpose of bringing it to another team member's attention.
Wireframe | (n.) A mockup of a user interface, usually created in a [workshop](workshops.md).
Zane | (n.) The teacher most completely tested with in the 'legacy' dataset - Zane Smith
