# 4. Generated Payload

We've seen how to use a hardcoded data structure as payload to the `UserList` component. Now we'll manufacture one for real.

## 4.1 Set up data in controller

Inject yourself a `\Schoolbox\UserMapper` instance inside the Greenhouse controller, then find all the users in our system.

```php
$users = $this->userMapper->findAll();
```

This is going to produce a lot of data that frontend doesn't actually need. We can minimise the amount of data passed to frontend so it operates mostly on facts and doesn't have to figure out answers for itself.

> That was something we experienced a lot while using twig, where a lot of business logic was being performed in frontend and it sometimes wasn't the same as backend.

```php
    public function getContainer(): void
    {
        $users = $this->userMapper->findAll();

        $data = [];

        foreach ($users as $user) {
            $data[] = [
                'fullname' => $user->getFullname(),
                'firstname' => $user->getFirstname(),
                'lastname' => $user->getLastname(),
                'role' => $user->getRole()->getName(),

                /* This could be generated by router(), for example
                 */
                'route' => "/search/user/{$user->getId()}"
            ];
        }

        $this->getResponse()->content->set($this->buildHtmlOutput('@greenhouse/container.twig', [
            'data' => $data
        ]));
    }
```

The data provided to twig is a set of `(fullname, role, route ...)` tuples instead of the fully-populated `User` instances. This establishes a _contract between backend and frontend_ layers in our application. The backend fulfils what the frontend expects to use.

Now we can pass this data to twig, who will then forward it through to Vue for us. We won't need the other example vars for now, so remove them from `prop` - we only need to use the `payload` prop.

In `container.twig`;

```html
<div id="user-list-container">
    <user-list :payload="{{ data | json_encode }}"></user-list>
</div>
```

In `user-list.vue`;

```html
<ul>
    <li v-for="(user, index) in payload" :key="index">
        {{ user.fullname }}, {{ user.role }}
    </li>
</ul>
```

After recompiling and refreshing, this will load a list of people next to their role names, in an unordered list.

> You can take that php and encapsulate it in a class whose purpose is specifically to produce that \$data payload. This becomes a highly cohesive, reusable class which can service a vue context and a non-vue context identically. If you're particularly attentive you can make it unit-testable too.
