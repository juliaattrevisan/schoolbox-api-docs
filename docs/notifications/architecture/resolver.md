# Resolver

The notification system uses a Resolver in its routing sub-system to determine
exactly which users should receive a Message, as determined by its Topics.

The Resolver is not concerned with how a Message is delivered to a user; only
with whether a Message is deliverable to a user.


## Glossary

<dl>
  <dt>Resolver</dt>
  <dd>
    A subsystem that is used to determine which users are subscribed to a 
    Message Topic.
  </dd>

  <dt>Message</dt>
  <dd>
    A payload that has been generated by another subsystem. It has one or more
    Topics.
  </dd>

  <dt>Topic</dt>
  <dd>
    A channel on which a message is to be broadcast.
  </dd>
</dl>


## Implementation

The resolver is implemented as a [trie](https://en.wikipedia.org/wiki/Trie)
data structure.


### Keys

The keys in the trie are in the same format as a Message's Topic.

> In theory, a Message may have more than one Topic; any user who's subscribed
  to any of these Topics will receive the Message.
>
> In practise, a Message is only ever assigned a single Topic.

#### Format

Example Message Topic:

`info.notify.service.1.43.1.forum.77.replied`

Words in a Message Topic are delimited by `.` characters. Each node (whether a
leaf or branch) within the trie is a single word.

#### Wildcards

A trie node may also be one of these wildcard values:
* `*` matches any single word in the Topic
* `#` matches any one or more words in the Topic

#### Examples

The following trie keys will match the above example Topic:
* `info.notify.service.1.43.1.forum.77.replied`
  * this is an exact match for the Topic
* `info.notify.service.1.43.1.forum.*.replied`
  * the wildcard `*` word matches `77`
* `info.notify.service.1.43.1.#`
  * the wildcard `#` word matches everything after it

The following will not match:
* `info.notify.serviced.1.43.1.forum.77.replied`
  * `serviced` doesn't match the word `service`
* `info.notify.service.2.43.1.forum.77.replied`
  * `2` doesn't match the word `1`
* `info.notify.service.1.43.1.blog.#`
  * Despite the `#` wildcard, `blog` doesn't match the word `forum` beforehand
`info.notify.service.1.43.1.forum.77.replied.#`
  * The `#` wildcard matches one or more words; there are no words after
    `replied`


### Values

Each value in the trie is a list; each item in that list will be one of either:
* an integer (corresponds to a user ID)
* a string (this key is aliased to another key in the trie)

The final value will be the union of:
* the integer values
* any integer values returned by resolving an alias key

#### User IDs

An integer value is treated as a user ID: this means that this user is
subscribed to this Topic.

#### Aliases

A string value is treated as an alias to another trie key: when the Resolver
sees an alias, it recursively looks up the value stored for that key, and
returns all users which that value resolves to.

The Resolver will throw an error if it detects circular references.

#### Examples

Looking up the key `info.notify.service.1.43.1.forum.77.replied` in the data
structure below:

```
[
    "info.notify.service.1.43.1.forum.77.replied": [
        1,
        3,
        6,
        10,
        "info.notify.service.2.43.1.forum.77.replied",
        "info.notify.service.2.43.1.forum.76.replied",
    ],
    "info.notify.service.2.43.1.forum.77.*": [
        1,
        3,
        9,
        15,
    ],
    "info.notify.service.3.43.1.forum.77.*": [
        11,
        19,
    ],
]
```

returns the following:
* users `[1,3,6,10]`
* any user found by looking up the key
  `info.notify.service.2.43.1.forum.77.replied`
  * this recursive lookup returns `[1,3,9,15]`
* any user found by looking up the key
  `info.notify.service.2.43.1.forum.76.replied`
  * this recursive lookup returns nothing
* the union of these values is returned: `[1,3,6,9,10,15]`

### Rebinding

> TODO figure out why rebinding happens only upon update, rather than create?

Any action within Schoolbox that changes the audience of a message must rebind
the values stored within the resolver.

These actions include:
* Changing the alternate source of a component
  * in order to notify users on the component's folder when the source
    changes, all redirects must be updated
* Changing a user's access to a folder
  * in order to determine which routes a user is subscribed to, all of their
    routes must be recalculated
* Importing users
  * all imported users must be rebound
