## Storybook

Our design system is built using [**Storybook**](https://storybook.js.org/). Storybook is an open-source tool used by developers to create and showcase individual components or UI elements in isolation. It allows for the isolated development, testing, and documentation of UI components, enabling teams to build and maintain consistent design systems. With Storybook, developers can interact with components in different states and variations, aiding in efficient UI development and collaboration.
In addition to providing tools to document our UI components, it also provides a platform for sharing documentation on our entire design system.

## Getting Started

To run Storybook locally use: `npm run storybook` within the `schoolbox` repo.

This will fire up a copy of Storybook in your Browser so you can contribute to documentation or develop your new UI in isolation with the added benefit of live reloading.
Our Storybook has been set up to implement our existing styles, so any styles used in Schoolbox can be used in Storybook.

In Storybook, a _story_ refers to a single instance or variation of a UI component, allowing developers to showcase and interact with it in isolation.
These are kept within the `/stories` directory and browsing the `/components` directory will give you a good idea of how to structure your own stories. Extensive [**guides**](https://storybook.js.org/docs/react/get-started/install/) and [**tutorials**](https://storybook.js.org/tutorials/) can also be found on the Storybook website.

To just contribute further documentation on our design system, Storybook utilises markdown files, which are also added within the `/stories` directory.
For example, review this page at `/stories/getting-started/Contributing.stories.mdx` to see how this page was created.
Upon saving changes or adding a new file, Storybook will automatically update to reflect your changes.

## Updating

To publish new stories or documentation, Storybook utilises a tool called [**Chromatic**](https://www.chromatic.com/).
Chromatic is a visual testing and review platform designed to work seamlessly with Storybook.
It automatically captures and compares UI component snapshots across different states and browser environments, enabling teams to detect visual regressions and ensure consistent design rendering.
By integrating with Storybook, Chromatic streamlines the process of visual quality assurance and facilitates collaborative feedback on design and UI changes.

To publish your changes using Chromatic, you'll need to add an Actions secret to your Github.
Within your forked `alaress/schoolbox` repo, select _Settings > Secrets > Actions > New repository secret._
The secret key value is stored in LastPass under: `CHROMATIC_PROJECT_TOKEN`

<a href="static/media/stories/assets/adding-secret.png" target="_blank">
    <img src={AddingSecret} alt="Adding Github Actions secret" />
</a>

With this setup, ensure your branch that contains the updates includes `-sb` in its name. For example: `task-develop-sb/SA-13017`

Branches so marked will update our online [**Storybook**](https://www.chromatic.com/builds?appId=619b379b58fbbb003a84d74d) with your latest changes whenever pushed.
To confirm that the branch is updating our Storybook, view the checks list on the pull request:

<img src={GithubActions} alt="Github actions" className="github" />

If you're experiencing issues with the automated Github action build, you can manually trigger a build by using: `npx chromatic --project-token=CHROMATIC_PROJECT_TOKEN` within the `schoolbox` repo.
Once Storybook has been rebuilt and pushed to Chromatic, your changes will be visible in the latest Storybook build. Now you can prompt others for feedback on your work.
To always be notified of our latest changes, be sure to join the _#storybook-updates_ Slack channel that is autoatically notified whenever a new Storybook build is pushed.
